# Domain Docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and decisions in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the work. If either is absent, proceed silently; `/domain-modeling` creates them when terms or decisions are resolved.

## Use the glossary

Use the defined domain terms in issues, proposals, hypotheses, and tests. If a concept is missing, reconsider the terminology or note the gap for `/domain-modeling`.

## Flag ADR conflicts

Explicitly surface any proposed work that contradicts an existing ADR rather than silently overriding it.
